# Pack Blueprints

> 先定模式，再写文档。结构不是装饰，它决定学习者会不会迷路。

---

## 1. 模式选择

### 1.1 规模

| 模式 | 适用 | 文档 | 正式图 | 动画 | demo | 自测 |
|---|---|---:|---:|---:|---:|---:|
| quick | “一小时速览”“先给提纲” | 3–5 | 1–2 | 0 | 1 | 15–20 |
| standard | 单篇论文/单个工具 | 8–12 | 3–5 | 0–1 | 2–3 | 40 |
| deep | “彻底学会/讲懂/完整教学包” | 15–25 | 6–10 | 2–4 | 5 | 60–100 |

默认 `deep`。如果用户没有明确说短版，不要擅自降级。

### 1.2 来源结构

| 模式 | 适用 | 关键动作 |
|---|---|---|
| single | 一个方法/一篇论文/一个工具 | 先补基础，再论文+代码 |
| series | 多篇论文/多个方法形成一条线 | 先全局地图与关系图，再逐个模块，最后横向对比 |
| project | 含用户自己的改进/实验 | 额外 reconstruct 研究时间线、失败与审计；分开“论文/代码/我的实验” |

### 1.3 学习者

| 类型 | 默认假设 | 写作偏好 |
|---|---|---|
| beginner | 不懂领域，但会基础编程/数学 | 直觉先行；公式给符号表；代码给最小可运行例 |
| practitioner | 会基础，想落地 | 代码、配置、工程坑优先；理论只保留够用的部分 |
| researcher | 懂领域，想判断证据 | 论文/代码差异、实验设计、边界、claim-evidence 优先 |

## 3. 一篇文档的职责

| 文档 | 只回答一个问题 | 必须包含 |
|---|---|---|
| 一页纸 | 这个主题一句话是什么？ | 3–10 个事实、1 张图、常见误解 |
| 论文精讲 | 论文为什么这么设计？ | 问题、公式、实验、边界 |
| 代码逐行 | 代码每一段在做什么？ | 文件地图、公式↔代码↔形状、逐行表、运行命令、练习 |
| 研究故事 | 用户的工作怎么做出来的？ | 时间线、复现、失败、审计、最终证据 |
| 方法公式 | 每个模块为什么存在？ | 符号表、公式推导、代码位置 |
| 实验设计 | 数据/队列/评估怎么组织？ | 数据协议、mask、baseline、冻结测试、统计 |
| 结果解读 | 每个数字说明什么？ | 主表、效应分解、机制、能说/不能说 |
| 踩坑复盘 | 哪些 bug 差点毁掉结论？ | 症状、根因、修复、教训 |
| 速查卡 | 考前/答辩前看什么？ | 公式、入口、术语、自测 |

## 4. series 模式：多篇论文一条线

不要写成“论文 A 摘要 + 论文 B 摘要 + 论文 C 摘要”。按这条线：

1. **全局地图**：一条主线 + 每条支线解决什么。
2. **共同记号表**：同一个符号在不同论文里是什么意思。
3. **接力表**：

| 论文 | 继承了什么 | 靶子是什么 | 改了什么 | 没解决什么 |
|---|---|---|---|---|

4. **逐个模块**：每篇论文 2 篇文档（精讲 + 代码）。
5. **横向对比**：方法、数据、评估、边界。
6. **你的工作**：放在这条线的哪个位置；哪些是继承、哪些是组合、哪些是新证据。

## 5. project 模式：用户自己的工作

必须分开三种叙述：

- **论文说**：原文的主张与数字
- **代码实际**：官方/用户代码真正做了什么
- **我的实验**：用户自己跑出的结果、失败、审计

研究故事按时间线写：

```text
复现 → 找缺口 → 假设 → 设计 → 踩坑 → 审计 → 补证据 → 成稿
```

每个阶段回答：

- 当时相信什么？
- 做了什么？
- 结果推翻了什么？
- 最后留下什么证据？

不要替用户编“灵感时刻”；从 git log、实验记录、交接文档、结果文件里找。

## 6. one-shot 完成定义

deep 模式一次交付必须同时存在：

- [ ] README 可点击总表
- [ ] 00 教学规格
- [ ] 00 全局地图
- [ ] 基础篇 3–5 篇
- [ ] 每个主题 2 篇
- [ ] project 模式的研究故事/方法/代码/实验/结果/踩坑/一页纸
- [ ] 5 个左右 demo，全部实际跑过
- [ ] 速查卡 4 份，自测 60–100 题
- [ ] 6–10 张 TikZ/drawio，全部编译/导出/插入
- [ ] 2–4 个 HTML 动画（有动态概念才做）
- [ ] 每篇顶部/底部导航
- [ ] 所有图片可点击
- [ ] `check_pack.py` 通过
- [ ] `compile_tikz.py` 通过
- [ ] 最终验收报告

数量是参考，不是硬指标。完整度按“学习目标是否被讲清、练到、测到”判断。
