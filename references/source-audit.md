# Source Audit

> 教学包最怕“听起来很顺，但数字和代码对不上”。先把来源钉死，再动笔。

---

## 1. 来源层级

从高到低：

```text
1. 用户自己的代码、配置、结果文件、日志
2. 官方代码（记录仓库、commit、文件 SHA256）
3. 论文原文（LaTeX/PDF，记录版本/页码/表图号）
4. 二手总结、博客、旧笔记
```

规则：

- 用户自己的工作以用户当前仓库为准；旧文档只作历史参考。
- 官方代码要记录版本；同一个仓库不同 commit 可能行为不同。
- 论文和代码冲突时，不要静默选一个；写成 callout 并说明采用哪个。
- 二手总结不能作为数字来源，只能提供线索。

---

## 2. 收料清单

### 论文

- [ ] PDF / LaTeX 源码
- [ ] 版本（arXiv v1/v2、期刊、会议）
- [ ] 摘要、引言、方法、实验、结论
- [ ] 所有关键 Table / Figure / Equation 编号
- [ ] 附录中的实现细节

### 代码

- [ ] 仓库路径、commit、分支
- [ ] 依赖版本（Python/PyTorch/CUDA/…）
- [ ] 入口脚本、配置文件
- [ ] 数据生成/加载逻辑
- [ ] 训练/评估/指标实现
- [ ] 已知 bug / 官方 issue / 用户修复

### 用户工作

- [ ] git log / 交接文档 / 实验记录
- [ ] 结果文件（summary/config/history/per-sample）
- [ ] 数据 manifest / SHA256
- [ ] 失败记录、审计报告、撤回结论
- [ ] 论文稿/图/表

## 3. claim–evidence 矩阵

每篇论文/每个方法建一张：

| 主张 | 证据 | 类型 | 强度 | 用在哪 |
|---|---|---|---|---|
| 方法 X 在数据集 Y 上降低误差 | 论文 Table 3 | 论文 | 强 | 主结果 |
| 代码实际用 5 点差分 | `physics.py:41-58` | 官方代码 | 强 | 方法/代码 |
| 我的 5 seed 均值更低 | `summary.json` + 聚合脚本 | 我的实验 | 中（描述性） | 结果 |
| 交互项显著 | 无检验 | 未验证 | 弱 | 不写/标推测 |

强度定义：

- **强**：可直接指到表/图/代码行，且有重复或审计。
- **中**：有单一来源，但未多 seed/未独立验证。
- **弱**：二手总结、口头描述、推测。

弱证据不要写进“结论”，只能写“待验证/推测”。

## 4. 论文 vs 代码冲突

标准写法：

```markdown
> **论文写法**：Eq. (3.13) 在 $j=0$ 不启用 U-Net 分支。
>
> **代码实际**：`models.py:88` 在每一层都调用 `unet(x)`。
>
> **本讲义采用**：代码实际；因为教学要能对应可运行实现。论文公式作为设计意图保留。
```

如果用户自己的工作与旧文档冲突：

```markdown
> **旧交接文档**：AC 只有 validation。
>
> **当前状态**：2026-10-27 已生成 250 样本 sealed test，5 seeds。
>
> **本讲义采用**：当前状态；旧文档标为历史。
```

---

## 5. 数字纪律

- 每个数字后面能追到：表号/图号/文件路径/字段名。
- 百分比变化写清基数：“相对 baseline 降低 50.1%”不是“降低 50.1 个点”。
- 均值 ± 标准差写清 seed 数。
- 不把“论文报告值”和“本地复现值”混在一张表里。
- 不把“验证集”写成“测试集”。
- 不把“post hoc”写成“预注册”。

---

## 6. 版本快照

在 `README.md` 或 `00_教学规格.md` 里记录：

```text
论文版本：
代码 commit：
数据 SHA256：
环境：Python / PyTorch / CUDA / 关键依赖
生成日期：
```

这样读者知道这套讲义对应哪个版本，不会拿旧结论套新代码。

---

## 7. 不确定性标注

用固定标签：

- `[论文]`：论文原文
- `[代码]`：代码实际
- `[我的实验]`：用户自己结果
- `[推测]`：没有直接证据
- `[待确认]`：来源冲突/缺失

教学文档里保留这些标签，比“看起来确定”更有价值。
