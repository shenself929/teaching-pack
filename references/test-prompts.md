# Test Prompts

> 用这 5 个 prompt 检查 skill 是否真的“通用、一次性、完整”。每个都在新会话里跑。

---

## Prompt 1：单篇论文 + 官方代码（deep，single）

> 把这篇论文和它的官方代码做成一套能自学的完整教学包。我要彻底搞懂方法、公式、代码每一段在干什么，还要有图、可运行 demo、自测题。不要只给提纲，一次交付。

预期：

- 自动选 deep + single
- 读论文/代码，建 claim-evidence
- 写 00 教学规格、00 全局地图
- 基础篇 + 论文精讲 + 代码逐行
- 至少 3 张 TikZ/drawio 图
- 至少 2 个 demo，实际运行
- 40–60 道自测题
- 导航 + README 总表
- 最终验收报告

失败信号：

- 只输出目录
- 没有代码逐行
- 图是文字占位符
- demo 没跑
- 数字没有来源

---

## Prompt 2：非代码主题（deep，single）

> 我想三天学会 Docker/Kubernetes，做成一套教程，不要只给提纲。要有学习路线、每章讲义、架构图、动手实验和练习题。

预期：

- 不硬套“论文/代码”模板
- 代码层替换为命令、配置、实验
- 图：架构图、数据流、状态图
- demo：可执行的命令清单/最小集群实验
- 自测题覆盖概念、命令、排错
- 不出现“论文说/代码实际”这类不适用标签

失败信号：

- 强行写“论文精讲”
- 只列命令不解释
- 没有练习
- 图只有 Mermaid 占位

---

## Prompt 3：系列 + 用户自己的工作（deep，project）

> 把 A、B、C 三个方法串成一条线，再重点讲清我的改进 D 是怎么做出来的。要讲清继承、差异、实验设计和失败记录。

预期：

- 先全局地图/关系图
- 共同记号表
- 每个方法 2 篇（精讲 + 代码）
- 用户工作单独成模块：研究故事、方法、代码、实验、结果、踩坑、一页纸
- 明确区分“论文说 / 代码实际 / 我的实验”
- 不把用户的工作写成“又一个模块拼接”

失败信号：

- 平均分配篇幅
- 没有关系图
- 把用户工作写成论文摘要
- 编造“灵感时刻”

---

## Prompt 4：Quick 模式（防过度建设）

> 只给我一小时速览，不要展开成二十篇文档。要能快速抓住核心概念、一个最小例子、十道自测题。

预期：

- 自动选 quick
- 3–5 篇文档
- 1–2 张图
- 1 个 demo
- 15–20 题
- 不生成动画、不强行 deep

失败信号：

- 仍然生成 20 篇
- 花大量时间画图
- 没有“一小时路线”

---

## Prompt 5：审计已有教学包（QA 模式）

> 检查这套教学讲义缺什么：导航、图、练习、代码对照、链接。给我一份修补清单，能补的直接补。

预期：

- 先跑 `check_pack.py`
- 输出缺失项清单：缺图、缺 nav、缺自测、断链
- 能直接补的补，不能补的说明原因
- 不重写整个包
- 最终报告修复前后对比

失败信号：

- 只给泛泛建议
- 不跑检查脚本
- 把“缺图”说成“建议加图”但不标注位置

---

## 评分

每个 prompt 按 5 项打分（0–2）：

| 项 | 0 | 1 | 2 |
|---|---|---|---|
| 模式选择 | 选错/不选 | 选了但没说明 | 正确选择并说明理由 |
| 来源纪律 | 编数字 | 有来源但不全 | 全部可追溯 |
| 教学完整度 | 只有提纲 | 缺练习/图/demo | 全齐 |
| 一次性 | 中途停下问 | 留 TODO | 一次交付完整 |
| 导航/验收 | 无 | 部分 | 全链接 + 报告 |

目标：每个 prompt ≥ 8/10。
